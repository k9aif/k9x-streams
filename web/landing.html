K9X ORIGIN

k9x Origin: one call for what is true right now

k9x Origin is built into the K9-AIF framework, like k9x Shield. An agent asks one question, get_current(entity, id), and gets the current value, when it changed, where it came from, and any reason not to trust it. K9X Streams is the reference demo you can run.

One callThe agent never chooses between streams, databases and APIs. Origin answers from live state, reads through to the system of record when it must, and says which it used.
Facts, not decisionsEvery answer carries as_of, source, version and flags. Whether a claim over $5,000 needs a person is a business rule, not Origin's call.
Governed in and outShield screens every event, every request and every answer. Each agent sees only the entities it is allowed to; conflicts and quarantined data are always flagged.
Read-only by designOrigin is for knowing. Actions go to the systems that own the data, carrying Origin's version, so they are refused if anything changed.

What it provides to a solution built on K9-AIF

A K9-AIF solution already has agents, squads, orchestrators and governance. K9X Streams adds the one thing a snapshot can't give them: the world as it is right now, delivered the way the framework already handles tools.

Live context over MCP

get_current, recent_changes and query, called with the framework's own MCP client (MCPStreamableHttpConnector). No new client code in your agents.

Facts the rules can use

Every answer carries as_of, age_seconds and version. Whether an age matters for a decision is a business rule, not something Origin decides.

Provenance on every value

Each value names the Kafka topic and offset of the event that set it, so a decision can be traced back to the exact record behind it.

Governed twice

Stream data is untrusted input. Every event passes k9x Shield at the gate (GovernanceEventGate, with PromptInjectionCheck and PaymentDiversionCheck); a refused event is quarantined, never applied. Each answer an agent reads is screened again (screen_tool_result).

Injected or on demand

The Orchestrator adds live_context for the entities a flow is about before the squad runs; an agent that must re-check just before acting asks over MCP.

Rebuilt from the stream

The live state replays from the topics on start, so Kafka stays the source of truth and a restart loses nothing.

Events that start agents designed

A rule on a stream ("payment posted for an invoice under review") publishes a domain event, and the K9-AIF Router starts a squad, the same way events work today.

How it works

Agents never read Kafka directly. A model can't drink from a firehose; at decision time it needs the current state and what just changed.

1 · INIncoming dataYour producers, change data capture from databases, or the demo's generator publish events.
2 · KAFKATopicsEvents land on topics: ap.invoice.updated, ap.payment.posted, ap.vendor.flagged.
3 · GATEScreenedk9x Shield checks every event. A refused one is quarantined: the entity is marked, its content never applied.
4 · STATELive stateProjections fold events into the latest value per entity, with as_of and the source event. Rebuilt from the topics on start.
5 · AGENTInjected, then re-checkedThe Orchestrator hands the squad live_context; just before acting the agent re-checks over MCP.

Built on the K9-AIF framework

K9-AIF (Agentic Integration Framework) is an architecture-first framework for building governed, secure, and enterprise-scale AI applications. Built on OOA/OOD principles and TOGAF-aligned, it brings consistency, governance, and auditability to agentic systems from day one. Every Router, Orchestrator, Squad and Agent in an application built on K9-AIF extends a K9-AIF Architecture Building Block, so governance, human review and auditability are inherited, not hand-built per application.

Security checks that keep pace with new attacks. AI is now used to attack applications that are themselves built with AI: instructions hidden in documents, agents impersonating other agents, poisoned tool results. K9-AIF tracks these attack techniques as they are published and adds matching checks to the framework's governance pipeline. Solutions built on K9-AIF pick up the new checks with a framework upgrade, without rewriting their own agents. K9X Sentinel reads newly published attacks every day and checks each one against the framework's security capabilities.

The K9X ecosystem brings the framework to life: K9X HIL (the human decisions an agent can pause for), K9X Sentinel (above), K9X Satan (an adversarial harness that proves the defences hold), and now K9X Streams, the reference demo of k9x Origin (K9-AIF 1.18): one governed call for what is true right now, built into the framework like k9x Shield.

Scope of this demonstration

  • The Accounts Payable events are simulated; there is no real vendor, invoice or payment data.
  • This demo holds live state in memory and rebuilds it from the topics on start. Shared live state in Redis is in K9-AIF 1.18 for clustered deployments.
  • One orchestrator, one squad and one agent with deterministic, explainable rules show the pattern; your squads get the same live_context and MCP tools.
  • A quarantined event is held for human review in the decision; raising it to K9X HIL (RequiresHIL) is the next step.
  • The demo's MCP endpoint has no sign-in; with real data it authenticates callers and Zero Trust scopes what each agent may read.
  • MCP resource subscriptions, stream triggers that start agents, and Avro with Schema Registry are designed, not built. Confluent Cloud settings are supported but not yet tested against a Confluent Cloud cluster.
